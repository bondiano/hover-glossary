# hover-glossary

Адаптивный словарь для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness): наведение курсора на слово в тексте сообщения пользователя или ассистента показывает всплывающую подсказку с **1 → N толкований**, а модель сама пополняет словарь доменными и проектными терминами из документации проекта.

Например, `WHO` показывает «1. Всемирная организация здравоохранения (аббр.); 2. кто (местоимение)». Поверх встроенного словаря работают два инструмента: `glossary_define` записывает термин в проектное или глобальное хранилище, `glossary_lookup` проверяет, не описан ли термин раньше. Раздел системного промпта объясняет модели, какие термины стоит записывать.

Это русскоязычный форк [AlyceStocking/hover-glossary](https://github.com/AlyceStocking/hover-glossary); дальнейшая разработка ведётся в [bondiano/hover-glossary](https://github.com/bondiano/hover-glossary).

## Текущая версия и совместимость

Текущая версия — **2.0.0** (русское издание). Во встроенном словаре 212 терминов и 236 толкований: объяснения и ключи терминов переведены на русский, английские и технические ключи (`WHO`, `API`, `token`, `KV cache`, `vLLM`, `Ascend`, `GLM-5.3-Flash` и другие) остаются как есть.

Совместимость с DSH `0.2.2-rc.3` проверена на уровне API: контракт загрузчика клиентских модулей, слот `shell.overlay`, маркеры `data-chat-flow-kind`, регистрация инструментов и секции системного промпта. Сам эффект наведения проверяется вручную в браузере.

## Установка и обновление

Установите плагин встроенной командой dsh (после установки он появится в разделе «Настройки → Плагины», где его можно включать, отключать и удалять):

```bash
dsh plugin --profile desktop add github:bondiano/hover-glossary
```

Пакет распространяется из GitHub: `dist/` собран и лежит в репозитории, отдельный шаг сборки при установке не нужен.

Пользователям Desktop: после установки полностью закройте и снова откройте приложение. Пользователям Web: замените `desktop` на `web`, перезапустите `dsh web` и откройте страницу по аутентифицированному URL, который печатается при запуске. После обновления плагина перезапустите Harness: host-половина читает хранилища при старте.

> Не устанавливайте плагин копированием в `node_modules` и ручной правкой `cordis.patch.yml`: так он запустится, но интерфейс управления плагинами его не покажет. Не заменяйте установку в профиль временными `cordis_define` / `cordis_run`, живущими только в памяти процесса.

## Хранение словаря

Три слоя, снизу вверх:

| Слой       | Файл                                           | Кто пишет                                                      |
| ---------- | ---------------------------------------------- | -------------------------------------------------------------- |
| встроенный | `src/domain/seed.ts`                           | разработчик плагина                                            |
| глобальный | `<DSH_HOME>/data/hover-glossary/glossary.json` | модель, `glossary_define` со `scope: "global"`                 |
| проектный  | `<project>/.dsh/hover-glossary.json`           | модель, `glossary_define` со `scope: "project"` (по умолчанию) |

Слои складываются в один словарь: сначала встроенный, затем глобальный, затем проектный. Внутри термина толкования сортируются по `weight` (по умолчанию 100), на термин хранится не больше восьми толкований. Проектный файл можно коммитить — так словарь проекта разделяется с командой; глобальный файл личный.

Оба файла — обычный JSON, их можно править руками:

```json
{
	"version": 1,
	"terms": {
		"Руна": [
			{
				"text": "внутренний формат обмена между слоями",
				"kind": "термин",
				"weight": 100,
				"source": "README.md",
				"scope": "project"
			}
		]
	}
}
```

Файл, который не удалось разобрать, не ломает плагин: он переименовывается в `<имя>.corrupt-<время>`, слой читается пустым, в лог хоста уходит предупреждение.

## Инструменты модели

- `glossary_define` — записывает одно толкование термина. Обязательные поля `term` и `gloss`, необязательные `kind`, `weight`, `source` и `scope`. Толкование пишется по-русски; дубликат текста не пишется повторно (`unchanged`, файл не трогается).
- `glossary_lookup` — ищет термин: сначала точное совпадение по нормализованному ключу, затем термины, содержащие запрос.

Гайденс в системном промпте просит модель добавлять доменные и проектные термины из доки и README, не записывать обычные слова и сначала проверять дубликаты через `glossary_lookup`.

## Обновление встроенного словаря

Единственный источник встроенного слоя — `src/domain/seed.ts`:

```ts
TERM: [
  { text: "первое толкование", kind: "аббревиатура", weight: 100 },
  { text: "второе толкование", kind: "местоимение", weight: 10 },
],
```

Чем больше `weight`, тем выше толкование в списке; при равном весе сохраняется порядок регистрации. После правок выполните `npm run check` (format → lint → typecheck → build + тесты) и закоммитьте обновлённый `dist/`.

## Поведение и границы

- Всплывающая подсказка показывает в шапке термин и количество толкований по-русски («1 значение», «2 значения», «5 значений»); ниже идёт нумерованный список с подписью категории (kind).
- Регистр, ширина символов и пунктуация не важны: `who`, `Who` и вариант в полноширинных символах попадают в один термин. При этом `WHO` не находится внутри `WHOLE`, а `токен` — внутри `токенизатор`.
- Побеждает самое длинное совпадение. Составные термины срабатывают с первого слова: при наведении на `United` в `United Nations` подсказка показывает весь термин.
- Учитывается только текст сообщения пользователя и ассистента; боковая панель, настройки, кнопки, ссылки и поле ввода пропускаются.
- Поиск ограничен одним текстовым узлом DOM: слово или фраза, разорванные по нескольким стилевым узлам, не склеиваются.
- Браузерная половина опрашивает `/plugin-api/hover-glossary/lexicon` раз в 30 секунд, пока вкладка видима, и по возврату фокуса. Изменения, записанные моделью, появляются без перезапуска. Роут только читает; мутаций от клиента нет.
- Пока словарь не загружен, подсказок нет — это тихое состояние, а не ошибка.
- Проектный слой один на процесс: подсказка показывает глобальный словарь и словарь того проекта, который последним трогал модель в этой сессии.
- Глобальный `window.__hoverGlossaryDiag__` доступен в консоли и показывает самопроверку: пробу каретки, классификацию зоны, `revision` и размер индекса.

## Разработка и проверка

```bash
npm ci
npm run check     # format:check, lint, typecheck, build + тесты
npm run build     # только tsc -> dist/
```

Архитектура повторяет `@local/dsh-role-team`: домен (`src/domain`), приложение (`src/application`), адаптеры (`src/adapters`), инфраструктура (`src/infrastructure`), презентация (`src/presentation`). Загрузка хранилищ и приём термина описаны явными машинами состояний XState v5 (`src/domain/machines`), схема файла хранилища декодируется через `effect` Schema, файловые операции обёрнуты в `Effect.tryPromise`. Корневые фасады (`index.ts`, `types.ts`, `config.ts`, `lexicon.ts`, `tools.ts`, `http.ts`, `state.ts`) реэкспортируют слои.

`npm test` собирает проект и гоняет `node --test dist/test/*.test.js`: лексикон и слияние слоёв, обе машины, интеграцию с фейковым HostContext (реальные файлы во временном `DSH_HOME`) и браузерную половину в `node:vm` (загрузка снапшота, ховер, паритет поиска с доменом).

## Распространение и включение в каталог

Тема GitHub `dsh-plugin` используется для включения в каталог dshfind; после добавления темы подождите обновления каталога. Установка из GitHub и публикация в npm — независимые каналы; этот форк npm-пакет не публикует. Пакет не объявляет `prepare`/`prepack`: `dist/` коммитится, поэтому pnpm ставит его из GitHub без `allowBuilds` — при установке build-скрипты не запускаются. Перед любой публикацией запускайте `npm run check` и `npm pack --dry-run`. Проект распространяется по лицензии MIT, см. [LICENSE](LICENSE).
